Overview

Designed and built a complete platform for Yar Ventures — a VC fund that needed to look as credible as the companies it backs, and scale as fast as its portfolio grows.

38+ portfolio companies filterable in real time across stage, vertical, and geography
4 CMS collections interconnected — one entry updates the filter page, logo marquee, and event archive automatically
Zero code changes needed — the entire site is managed by a non-technical team

Challenge

A growing fund with no digital presence

Yar Ventures had a portfolio, a community of Silicon Valley LPs, and monthly pitch events — but no website that communicated their scale or credibility. Investors needed a way to browse companies; the team needed to update it themselves.

Approach

System design first, visuals second

Built around a multi-collection CMS schema before a single visual was designed. The portfolio filter — stage, vertical, HQ, and live search — was architected using Webflow CMS multi-reference fields and Finsweet CMS Filter for a product-grade experience.

Outcome

A site that runs itself

Adding a new portfolio company takes minutes. The homepage marquee, filter page, and all listing views update automatically. The design signals institutional trust — and the system behind it is built to scale to hundreds of companies.

Design

Credibility without coldness

Designed to feel trustworthy and structured — without looking corporate or rigid.

Minimal palette, editorial typography, and restrained motion keep the focus on content.

Key Feature

Real-time filtering at scale

Investors explore 38+ portfolio companies instantly — combining dropdown filters with live text search in a single, seamless flow. Every interaction updates results immediately. No page reloads. No friction.

02 Webflow · Community · CMS Architecture

Persian Tech
Network

From recurring events to a living archive — a platform that captures and connects a community over time.

Visit Live Site
Webflow CMS Architecture Community Platform Event System UI Design

Overview

Four years of monthly gatherings, 8,150+ people, 29 events — and a platform designed to get lighter as the archive grows heavier.

29 events, 40 speakers, 60 startups — not isolated entries, but a connected system where relationships are as visible as the records.
A living archive — every gathering adds to a growing, searchable record that reflects the community's trajectory over time.
One entry, fully managed — a non-technical team runs the entire cadence. No duplication. No drift between what happens and what's published.

Challenge

A growing community, a growing maintenance burden

Each month brought a new event — along with speakers, startups, and flyers — but no structure connecting them. Content lived in isolated pieces, making it harder to manage, scale, and reflect the community as a whole.

Approach

Model the community, not the content

Instead of designing pages first, the system was built around relationships — events, speakers, and startups as connected collections. The website became a layer on top of structured data, not a container for disconnected content.

Outcome

An archive that grows itself

A single CMS entry per event populates the entire platform — from homepage sections to archive pages and profiles. As new events are added, the system expands automatically, without duplication or manual updates.

Design

Editorial, not ornamental

The design stays intentionally minimal — not to stand out, but to support clarity at scale. As the archive grows, typography and spacing carry the hierarchy, ensuring content remains readable and structured over time.

Rather than adding visual complexity, the focus is on consistency, predictability, and making relationships easy to scan across events, speakers, and startups.

Key Feature

One entry.
Every surface.

A single CMS entry — one event — updates the homepage, populates the archive, extends speaker profiles, and adds to the startup directory. No templates to touch. No syncing required.

CMS Architecture

Four collections.
One community.

Events are the central collection — every other collection connects to them. Speakers and Startups are independent profiles referenced by multiple events. Flyers form a separate image archive that auto-populates the archive page. No content is duplicated; everything is referenced.

Events

Central collection. Holds the date, flyer, registration link, and multi-reference fields to Speakers and Startups

Speakers

Referenced by Events. One speaker entry — name, photo, LinkedIn — appears across every event they participated in

Startups

Referenced by Events. Each startup entry links to the event where it pitched — building a searchable directory over time

Flyers

Separate image collection. Each flyer is its own entry — auto-populates the archive grid without any manual page updates

Relational schema

Add one event. The rest of the site updates itself.

Connected Experience

From event to everything else.

Each event becomes an entry point — linking to the speakers, startups, videos, websites, and LinkedIn profiles tied to that gathering.

03 Fintech SaaS Landing Page · Webflow

Primer

Class Project

Building a fintech landing page that behaves like a real product — not just a static layout. Focused on structure, interaction design, and long-form conversion patterns within the constraints of Webflow.

Visit Live Site
Webflow UI Design SaaS Layout Interactions Pricing Toggle Responsive
Primer•••

Balance

$12.4k

Overview

Exploring how far Webflow can go — by building a fintech landing page that mimics real product behavior.

Structured as a long-form conversion flow — moving from clarity to decision without overwhelming the user
Interactions used intentionally to guide attention, not decorate — including pricing toggles, scroll reveals, and motion cues
Built entirely without custom code — pushing Webflow's native capabilities to their edge

Brief

Design a fintech landing page that converts — not just visually, but structurally

The constraint: build a page a real product team could ship, using only Webflow.

Approach

Start with structure, then layer interactions

The page was mapped as a long-form flow — from value → features → pricing → action — before any visual styling.

Outcome

A landing page that behaves like a product

Interactions are used to guide attention and reduce friction across a long-scroll experience.

Design

Minimal input, maximum clarity

The visual direction is intentionally restrained — a light interface, strong typographic hierarchy, and product UI used as the primary visual proof.

Instead of relying on decoration, the design focuses on structure. Each section moves from broad value to specific features and pricing, guiding the user through a deliberate long-form flow.

Key Feature

Interactions that earn attention

Every animated element serves the layout — not the other way around. The pricing toggle reduces friction at the decision point, while scroll reveals pace the reading flow. Motion is used to guide attention, not decorate.

01 / Primary

Pricing toggle

Switches between monthly and yearly plans with smooth state transitions — allowing quick comparison without interrupting the decision flow.

02 / Scroll

Scroll reveals

Staggered content reveals control pacing across the page — preventing information overload in a long-form layout.

03 / Motion

Word marquees

Subtle, multi-directional motion reinforces key terms and creates rhythm without distracting from the content.

04 / Proof

Floating mockup hero

Layered mobile UI with depth and slight motion establishes product credibility before a single word is read.

05 / System

Feature card grid

Hover and scroll-based interactions turn static content into a browsable, scannable system.

06 / Responsive

Responsive breakpoints

Interactions adapt across screen sizes — maintaining clarity and consistency without layout breaks.

Pricing toggle interaction

A focused demo of the primary decision-point interaction.

What I Practiced

Webflow from first principles

This project was built to demonstrate mastery of the Webflow toolkit — not just the visual output, but the thinking behind structure, performance, and interaction design.

Webflow Interactions — scroll-triggered animations, toggle states, hover effects, all without custom code
Responsive layout system — breakpoints from desktop to mobile without any layout breaks or overflow
Typography hierarchy — headline, subheadline, body, and caption working together across a long-form page
Asset optimisation — .avif and .svg formats throughout for performance without visual compromise
SaaS page architecture — hero → proof → features → pricing → CTA as a deliberate conversion funnel
